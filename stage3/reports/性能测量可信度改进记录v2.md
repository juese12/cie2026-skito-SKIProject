## 测量合同

| 项目 | v1 | v2 正式 |
| --- | --- | --- |
| 预热 | 每实现/内核一次 | 每实现/内核八次，记录首末周期 |
| 长度 | 32 批/128 点积 | 256 批/1,024 点积 |
| 重复 | 同一进程五次 | 同一进程八对 + 默认四个新进程 |
| 顺序 | 固定 vdot → RVV | 每对交替；进程起始顺序 0/1/0/1 |
| 打印 | 每次采样后 | 所有计时和检查结束后统一打印 |
| 边界 | 两次裸 mcycle | 固定 XS 的 CSR-write 串行标记 |
| 检查 | 测量完整输出 | 预热/测量完整输出与向量 CSR |
| 统计 | 中位数/比值 | 原始值、范围、CV、漂移、位置/起始顺序影响 |

正式仍为双方各 1,032 个 oracle 等价性检查。烟雾为双方各 32 定向、2 轮预热、4 对样本、每次 8 批/32 点积、两个新进程，仅验证流程，不作为正式性能。精确宽乘/宽归约的 RVV 基线与 vdot 语义不变。

随机输入仅用于等价性检查。计时输入固定为低八项 a=1、b=2，其他字节为干扰值；chain 为零固定点。不是跨数据分布/GEMM 工作负载测量。编译器 `riscv64-linux-gnu-gcc 15.2.0`；AM 基线 （nexus-am），实际修改及镜像须结合构建日志与 追溯。

## 计时边界的依据与开销

当前固定 XS 的 `Rename.scala` 约 281–299 行会对普通 CSR 只读去掉 waitForward/blockBackward；mcycle 不在 `CSROoORead.scala` 保留顺序的列表内。不能仅从两次读计数器的程序顺序推导向量操作已结束。

v2 汇编采用：

```text
初始化与选路
csrwi vstart,0 排空前序；计时外
csrr t1,mcycle
csrwi vstart,0 等待起始读完成并阻塞年轻操作；计时内
实际内核
csrwi vstart,0 等待内核完成；计时内
csrr t3,mcycle
差值、输出保存、自检
```

`DecodeUnit.scala` 的 CSRRWI 设置 noSpec/waitForward、blockBackward，且不是 Rename 的只读特例。`NewDispatch.scala` 约 801 行的 waitForward 等待 ROB 空；`Rob.scala` 的 hasBlockBackward 阻止后续入队，直到 ROB 再次为空。vstart 本来为零，VS 开启，每次自检验证最终状态。

这只适用于已核查的 XS 实现，不是任意 RISC-V 的通用屏障。计时包含两条串行标记和恢复开销，不相减空循环，不称作孤立 FU 延迟。ROB 空也不等于 e2e 存储已写到 DRAM；计时包含程序存储操作，不是外部内存持久完成时间。换核版本须重查。静态反汇编已确认标记；专门动态时间戳/ROB 边界波形尚未取得，属于后续延迟证据工作。

## 操作入口与统计验收

在 xs-env 根目录：

```bash
bash cie2026-skito-SKIProject/scripts/build-vdot-bench.sh --smoke
bash cie2026-skito-SKIProject/scripts/run-vdot-bench-series.sh --smoke
bash cie2026-skito-SKIProject/scripts/build-vdot-bench.sh
bash cie2026-skito-SKIProject/scripts/run-vdot-bench-series.sh
```

正式四进程可能耗时数小时，先验证烟雾。`validate-vdot-core.sh` 的单次 benchmark 仅作整核集成验收，不能替代正式 series。新镜像/对象与 v1 分离。runner 记录命令、起止、emu/ref/image 和过程退出码；行缓冲、唯一日志、防覆盖/并发；series 每次启动新 emu，均衡初始顺序，失败即停。运行脚本先复制到唯一 snapshot 目录，再执行固定快照，保留 runner ，避免编辑源脚本造成在途 Bash 读取偏移错误；snapshot 目录忽略 Git，保留在本地。输出在 `stage3/logs`，操作索引在 `stage2/logs/operations.tsv`。

作品仓库内可对已知正式队列设置报告接续：

```bash
bash scripts/finalize-vdot-bench-report.sh stage3/logs/实际正式series.paths
```

该入口等待在途队列锁释放，重新审计清单中所有完整 full.log（不信任已打印的统计文本），拒绝少于四进程、烟雾、缺失/损坏或混合版本的数据。输出 `stage3/reports/vdot正式性能实测报告v2.md` 和同队列 `-report.json`，均防覆盖。专门单测中的合成数据只能生成明确标注的合成测试报告。重新复算可直接调用 `render-bench-report.py --manifest ... --output /tmp/新报告.md --json-out /tmp/新报告.json`，不覆盖已交付报告。

分析器严格核查协议、双方等价性、完整样本、执行顺序和预热摘要，v2 必须包含且仅包含一次 `[process exit] 0`；拒绝混用参数或 emu/ref，同一顺序须使用同一 image；拒绝重复路径/内容。JSON 保留原始值、配对比值、各进程中位数和比值。跨进程不池化样本、不宣称置信区间；四次确定性仿真也不代表现实芯片的随机独立样本。

作品仓库内复算实际 series 清单：

```bash
mapfile -t logs < stage3/logs/实际series.paths
python3 stage3/tests/analyze-bench.py "${logs[@]}" --json-out /tmp/vdot-series-audit.json
```

阈值是项目启发式门槛，非官方标准；数据有效退出 0；严格模式不稳定退出 3，数据无效退出 1。

已完成结果及当前复核方式见[版本与复核入口](../../docs/核与参考库版本选择.md)。

原 `.paths` 清单含运行机绝对路径；迁移仓库后可采用上述相对路径入口，不必修改原始日志。未完成的队列必然被分析器拒绝。

新增校验：`test-analyze-bench.py` 使用显式人工 fixture，不是硬件数据；Python -O 下仍拒绝错误。`check-bench-image.py` 仅审计 ELF 中计时标记、批次 ABI 与无函数调用，不冒充动态证明。

该偏差也可能受预热/测量外部控制流影响，不能单独归因于缓存。
