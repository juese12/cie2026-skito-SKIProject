# NEMU 扩展与协同仿真验证报告

## 当前实现与指令语义

验证对象为当前 `sew16-fixed8` e8/e16 设计，参考库为 `NEMU/build/sew16/riscv64-nemu-interpreter-so`。VLEN=128、LMUL=1、VL=8、vm=1、vstart=0；e8 求低八字节的精确有符号点积，e16 求八个半字的精确点积。

e8 输出低 32 位补码、高 96 位零；e16 输出低 64 位补码、高 64 位零。不累加旧目的，不舍入、不饱和。完整语义见[当前设计](../../stage2/docs/vdot指令设计说明.md)。

## NEMU 修改通路

下列路径相对 `NEMU/src/isa/riscv64/`，交付代码见[完整 NEMU 补丁](../../stage2/patches/nemu-vdot-sew16-fixed8.patch)。

| 文件 | 作用 |
| --- | --- |
| `instr/decode.c` | 精确识别 custom-0 指令族，使用向量寄存器字段 |
| `instr/rvv/decode.h` | 分派至 vdot helper |
| `include/isa-all-instr.h` | 注册指令入口 |
| `instr/rvv/vcompute.h` | 检查配置，独立计算八项和并完整写回目的 |
| `system/intr.c` | 精确对齐本指令族仅 VL 不合法时的异常 tval 行为 |

helper 先执行向量使能与合法性检查，再逐项把字节或半字补码解释为有符号整数，以 `int64_t` 求和。所有源读取完毕后才写目的，支持源目的别名。硬件使用并行乘法与平衡树，参考模型使用顺序整数循环；另外由测试程序和分析工具的独立整数参考计算检查结果。

非法配置产生非法指令异常，不提交目的结果。仅 VL 非法时，本平台执行阶段异常的 tval 为零；其他非法条件保留其对应平台行为。该适配只作用于指定 vdot 条件，没有关闭整个异常字段比较。

## 协同仿真机制

同一裸机程序在香山 RTL 中执行，ROB 按程序顺序提交；Difftest 按提交推进 NEMU，并比较架构状态。NEMU 不模拟相同硬件流水时钟，两侧以指令语义和提交结果对齐。

软件使用完整寄存器保存结果，检查 128 位目的与相关配置 CSR；异常用例还核对 cause、PC、tval、目的保持和恢复。错误路径指令的 FU 结果可以出现，但被取消的 ROB 分配代次不得提交。完整通路及实际信号见[当前整核图解](../../stage2/reports/e16整核仿真与关键信号图解.md)。

## 测试范围

功能用例覆盖正负数、极值、零、ta/ma、v0/v31、寄存器别名、配置切换、普通乘法混发、依赖链、异常恢复和实际执行后取消。多数据种子与多初始化进程分别计数。有限动态测试不外推为全部控制流、任意背压或其他 VLEN 的形式证明。

协同仿真说明已覆盖程序的状态一致性；FU 端口延迟、内核周期和应用收益分别使用[延迟分析](基线与vdot延迟加速图文分析.md)及 GEMV 报告的测量边界。
