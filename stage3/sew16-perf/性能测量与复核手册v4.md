四个预飞和八个正式进程全部差分/GOOD TRAP/真实退出 0；入口：[完整正式报告](../reports/e8e16正式性能分析报告v4.md)、[分析 JSON](../logs/20261027T190338-sew16-perf4-full.analysis.json)、[全部采样 CSV](../logs/20261027T190338-sew16-perf4-full.analysis.samples.csv)、[最终重审](../logs/20261028-sew16-perf4-final-review.json)。

固定 RTL，不覆盖旧程序/数据。正式核为 `XiangShan/build/sew16-fixed8/emu`，参考库 `NEMU/build/sew16/riscv64-nemu-interpreter-so`；旧 e8 隔离核另配旧参考库，只执行同一镜像的 e8 路径，用于逐种子比较扩展前后 e8 周期。所有路径都保留在同一镜像中，启动前只覆盖独立八字节参数对象。

## 预先固定的合同

- 当前核比较 e8/e16 各自 vdot 与精确标准 RVV。e8 为 signed8 宽乘至 signed16，再宽归约至 signed32；e16 为 signed16 宽乘至 signed32，再宽归约至 signed64。双方完整 128 位结果、高位零及返回后的 VL/vtype/vcsr/vstart 一致。
- 三类内核：四独立目标的 batch4；含源加载、目的初始化和结果存储的 e2e；单寄存器真实反馈 chain。chain 分别使用 3 种长度，合计每位宽 5 个测量场景。
- chain 的 lane0 初值为 e8 的 37、e16 的 257，乘数 lane0=3，其余为零；下一步按结果低元素的有符号解释反馈。有界奇数序列始终非零，独立 C oracle 逐步确认无固定点并按指令完整打包语义计算终值。该受控序列用于隔离反馈依赖，不冒充真实应用分布。
- batch/e2e 使用由进程参数数据 seed 生成的固定非零向量，每次计时之后检查结果；其余随机等价性检查在计时前完成。全程差分，成功路径打印延后到所有计时结束。
- 继承已有 `csrwi vstart,0` 排空/计数器边界方法。先用当前事件模型核验新镜像的 marker/read/body 提交顺序，再允许正式队列；不把旧核边界证据自动当作新程序的动态验收。

## 指标与拒绝夸大

各进程先取自身样本中位数及 RVV/vdot 比，再汇总四进程，不能把同一进程的样本当成独立进程。空循环不扣除。多链长拟合只描述有效依赖链周期斜率和残差，不称纯 FU latency；FU 两周期另由实际端口事件确认。

该协议改变了数据、长度和场景，旧 v3 加速比不混入本轮统计。扩展前后 e8 的比较只使用本轮同镜像同参数数据；不将周期变化解释为物理频率、面积或功耗变化。无工艺库，本轮不做综合/STA/PPA。不为性能采集完整波形；长整核任务每 40 分钟检查一次，保留失败和恢复记录。

同主机独立目录已重建当前核、参考库和本性能镜像，并运行 first=0/1 两个新核烟雾：每进程、每位宽、每实现 40 项等价性检查，合计 320 项，保留 240 条采样，独立 oracle 与差分均通过。它们只验收新构建组合，不替换原八进程正式测量，详见[独立目录报告](../../stage2/reports/公开包独立目录复现报告.md)。

实际运行均通过 `scripts/vdot-step.sh` 留操作日志和真实退出。预飞为一个事件 probe、两次新核均衡 smoke 和一次旧核 smoke；正式为新旧核各四进程，同一轮按种子配对并交替核顺序。中断时 `series.py` 可加 `--resume EXACT.state.json`；它只复用已核对完成的进程，失败尝试用新后缀保留。默认数据审核通过返回 0，两者分开报告。

成功路径输出采用 `perf4 seq`，按位宽、场景、阶段和实现保存完整周期数组，减少重复打印长标签的开销。全部预热和正式值均保留；`rep` 是数组下标，槽位按既定规则 `impl XOR first XOR (rep&1)` 恢复。分析器将数组展开为逐样本记录，并检查压缩前后的数值一致。

计时边界审计对四个真实汇编内核各检查 42 次完整调用（probe 的定向等价性和计时调用）：前置排空、起点读、起始标记、实际 body、结束标记、终点读的 ROB 分配/提交顺序；同时核对 dot 两周期输入/输出、配置和完整 128 位 oracle。它不证明通用 ISA fence，也不证明数据已经持久写入 DRAM。

四独立目标共用同一对源向量，用于测量指令流，未将它包装为四组不同输入的应用工作。e2e 定义包含双方共同的目的/seed 初始化框架，不能称为所有可能实现中最快的端到端算法；batch4 将初始化放在计时外，供计算通路对照。计时向量和预期值全部打印保存，分析器用独立 Python 整数重新计算。
