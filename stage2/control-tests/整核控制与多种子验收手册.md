# 整核控制与多种子验收

版本范围：本目录默认保留旧 e8 隔离核合同，`run-vdot-control.sh` 仍默认选择 `build/operand-isolation/emu` 和旧参考库。共享源码现在由 `VDOT_TEST_E16` 区分合同；当前 e8/e16 的[适配入口](../contract-tests/旧测试约定适配手册.md)选择 1，以 e32/e64 测最终非法配置并核验 VL=4/2。下面的表格、四种子记录和命令描述默认历史合同；旧镜像不能直接配新核。当前主功能入口及整组产物见[版本选择](../../docs/核与参考库版本选择.md)。

本目录独立于原 `vdot-tests`，不覆盖已有比赛功能镜像。当前 v0.1 契约仍是 e8/m1/VL=8/vm=1/vstart=0 的低8个有符号字节点积，低32位结果及高96位清零；所有 ta/ma 组合均合法。这里测试依赖和取消，不扩充指令语义。

## 测试设计

| 项目 | 每个种子的覆盖 | 判定 |
| --- | --- | --- |
| 分支错误路径 | 同一个静态分支16次不跳转训练后1次跳转，重复4轮；六级真实除法依赖延迟分支解析，年轻 vdot 写 v20/v0 | 探测轮完整128位毒值及 VL/vtype/vstart/vcsr 不变；波形还必须出现 taken+mispredict、对应 ROB 标签、两个 vdot 的实际 Vimac 输出、接受重定向、同一分配不提交 |
| 非法指令的年轻 vdot | 4次非法32位指令；后接写 v20、v0、vs1=vd 的 v21；前置除法链延迟精确异常 | trap 精确 cause/mepc/mtval；handler 跳过整个年轻区间，不回放；三个完整128位毒值不变；波形必须确认三个年轻 vdot 均执行后被异常冲刷且不提交 |
| 连续合法配置切换 | 24组随机输入、全部 ta/ma；SEW16→VL7→合法，VL16→合法，VL0→SEW32→合法；每组3个 dot | 不在配置与 dot 之间插入 CSR 读串行化；每个结果完整128位正确，最终 VL/vtype/vstart/vcsr 正确 |
| 最后一次配置非法 | 16组，合法→最终 VL7，或合法→最终 SEW16，全部 ta/ma | 不能错误使用之前合法配置；非法 dot 不写目的，精确异常；恢复前记录 VL/vtype，随后恢复合法配置 |
| 混发/真依赖 | 16组随机输入，每组32次 vmul→dot→vmacc→dot v0→dot读v0→vmul读v0→dot链 | 普通乘法的模256结果/尾部保留、dot完整结果、v0与别名依赖及 CSR 独立 C oracle 检查 |
| 长链 | 16组随机输入，各128级 dot v0→dot读v0 | 每级输出的低4个有符号字节反馈为下一次输入；不使用恒零或假依赖作为长链覆盖 |
| 多种子随机 | 每个 seed 各256组，11种别名/目的/v0/二级dot/mask消费者模式，全部 ta/ma | 独立 xorshift 输入流、镜像、对象目录和精确 seed PASS；不将同 seed 增量记为多 seed |

软件种子：`56444f54`、`00000001`、`9e3779b9`、`deadbeef`；对应完整仿真独立初始化种子 101/202/303/404。波形运行另外重复第一个软件种子及初始化101，以保留可复查的推测控制证据。

## 操作手册

在项目根目录 `cie2026-skito-SKIProject/`：

```bash
bash scripts/build-vdot-control.sh
python3 stage2/control-tests/test_control_audit.py
bash scripts/vdot-step.sh isolation-core-build bash scripts/build-vdot-isolation-core.sh
bash scripts/vdot-step.sh isolation-regression bash scripts/run-vdot-isolation-regression.sh
```

整核构建只生成 `../XiangShan/build/operand-isolation/`，不覆盖默认或 P1 emu。构建锁禁止同类重复执行；回归自动等待构建锁释放，再确认可执行文件与原源文件/基线/ref 版本。生成脚本检测已有 emu/FIR 后拒绝覆盖，恢复中断时应查日志并从未完成阶段继续，不能盲目重建。长任务必须使用可轮询的持久执行会话；在沙箱里启动 `nohup &` 然后结束会话不能保证子进程存活。

回归先运行原52合法/10非法烟雾，再运行原1052合法/10非法完整功能测试，随后四个独立控制进程和单独波形进程。`run-vdot-control.sh` 记录 emu/ref/image 文件、命令、实际退出状态，并要求精确 seed/计数 PASS、差分开启、GOOD TRAP、无 FAIL/ABORT。日志进入 `stage2/logs/operations.tsv`；整个套件最后复核固定版本。

服务器中断恢复时先检查原会话、host进程和锁，再检查各项完整日志与实际退出码。缺少GOOD TRAP/精确PASS/实际退出记录的尝试不能补写为成功；已完成的构建或种子无需重复。复核原固定清单和源码版本 一致后，仅继续未完成项，并为重跑使用新的波形/日志/JSON路径，不覆盖中断证据。若只剩波形项，应依次完成新的完整波形运行、对应日志/符号/波形联合审计、固定清单和源文件/原核/ref复核。 实际恢复命令已记录于[整核报告](../reports/隔离版本整核构建与控制验证报告.md)所指的 `isolation-regression-resume.full.log`；原中断外层日志没有套件PASS，不将恢复成功伪装成原进程成功退出。

单独复查一个种子：

```bash
CONTROL_SEED_HEX=deadbeef bash scripts/run-vdot-control.sh --seed=404
```

`check-vdot-control.py LOG --seed HEX --json-out NEW.json` 只审核架构结果，输出 `control_status=NOT_AUDITED`，绝不能作为错误路径证据。加 `--wave VCD --symbols SYMBOLS` 才做真实整核控制审计；要求真实信号存在且非未知、ROB 环形标签顺序、实际执行、精确冲刷和后续提交/恢复覆盖。不存在推测执行或波形过早结束时必须失败。审计器的合成正反例只检验审计器，不能替代处理器回归。

波形窗口默认 0–26000 cycle，保留原始 VCD、原始提交日志和 JSON 事件索引。控制 runner 将 `--dump-wave` 规范为 `--dump-wave-full`，实际命令也记录规范后的参数：前者只有每周期高相位快照，后者包含双相位，审计器固定在稳定低相位关联事件。若未覆盖首次探测/异常或目标 dot 的实际执行，应根据观察调整测试/窗口后重跑，不能降低证据门槛。该定向验证不是对所有分支/异常/全状态的形式化证明，也不是功耗或 PPA 验收。
