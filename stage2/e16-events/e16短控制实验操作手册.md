# e16 短控制实验与稀疏事件

补强当前 `sew16-fixed8` 的内部取消证据和独立初始化种子覆盖。功能主入口仍见[版本选择](../../docs/核与参考库版本选择.md)，实验状态及真实结果见[实验报告](../reports/e16整核取消与独立初始化实验报告.md)。不覆盖旧整核、原成功镜像、参考库或历史日志。

## 固定实验协议

使用已通过验收的 `XiangShan/build/sew16-fixed8/rtl` 和 `NEMU/build/sew16/riscv64-nemu-interpreter-so`。独立事件模型保存在 `XiangShan/build/sew16-events`；仅通过 Verilator `public_flat_rd` 保留选择的观测端口，并在仿真器时钟低电平稳定后读取，不修改 RTL 功能，不打开波形支持。

短程序的四组数据种子为 `56444f54/00000001/9e3779b9/deadbeef`。每组包含两轮，每轮先进行 16 次合法分支训练，再做一次反转探测和一次非法指令后的年轻 e16 探测。每个进程共 128 次合法训练、8 次分支探测、8 次精确非法异常。首组八个 `-32768 × -32768` 的结果是 `8589934592`，用于排除错误使用 e8 数据或只检查低 32 位的假通过。

整核初始化种子固定为 `101/202/303/404`，每个种子启动独立进程，各自运行上述四组数据。先在同一个事件模型上比较 seed=101 的记录关闭/开启运行，要求完整架构提交文本、指令数和周期一致；开启运行同时作为四进程中的 seed=101，不重复运行。其他三个进程只记录稀疏 JSONL 和常规日志。

## 证据判据

每条目标指令通过 PC、ROB `flag/value` 和分配代次关联。分配必须满足 `req.valid && canAccept && firstUop`，避免把普通 RVV 展开的微操作重复算成架构分配。提交使用 ROB 的 `isCommit && commitValid`，排除恢复 walk。

每个初始化种子必须至少观察到一组完整的分支取消，以及一组完整的非法异常取消：

1. 目标 PC 已分配 ROB；实际 FU 接收配置为 SEW=16、VL=8、m1、vm=1、vstart=0、vill=0。
2. 接收的两组完整 128 位源数据经独立 Python 有符号半字 oracle 计算，匹配两级流水输出的完整 128 位结果。
3. 分支经实际误预测决策和控制块接受的 redirect 确认；异常经 ROB flush 及下一拍精确 illegal 异常载荷确认。
4. 所有目标输出在相应取消事件之前或同拍出现；同一分配代次此后没有架构提交；分支自身提交或异常恢复地址提交，证明运行越过恢复尾部。
5. 合法训练路径的两个 e16 PC 均有结果和提交；软件同时核对目的寄存器、v0、CSR、精确异常及 NEMU 差分。

分支预测器可能预测正确，因此 8 次探测不等于 8 次实际取消。报告保留每个进程实际覆盖数量；缺覆盖、错误、截断、缺 footer 均不能按 PASS 处理。全部尝试保留，协议修改须新建实验前缀重新执行。

## 文件和运行

`main.c` 是短程序；`control.S/trap.S` 复用控制汇编，显式选择 e16。`visibility.vlt` 定义只读观测范围，`collector.h` 定义低电平稀疏事件格式，`audit.py` 负责离线关联与数值检查，`test_audit.py` 检查审计器能拒绝伪覆盖和错误结果。

实验已完成，可使用报告中的 `check-experiment.py` 命令复核。四个不同初始化 seed 的有效事件轨迹相同，不能据此声称获得四种不同控制历史。宿主记录可能穿插串口输出，审计器先去除已知宿主文本，再检查程序摘要，同时保留原日志的错误检查。首个关闭记录的运行日志经核对输入后复用，首次解析失败的记录也保留。

从作品根目录执行（已有构建/实验产物时先检查历史记录，不重复覆盖）：

```bash
source ../env.sh
make -C stage2/e16-events ARCH=riscv64-xs
python3 stage2/e16-events/test_audit.py
python3 scripts/build-e16-event-emulator.py
python3 scripts/finalize-e16-event-collector.py
python3 scripts/run-e16-event-experiment.py
```

运行通过 `scripts/vdot-step.sh` 记录日志和实际退出状态。初始构建后，观测器增加 `firstUop` 门控与格式标记，再重新编译、链接；初版程序归档为 `emu-initial-collector`，实验使用 `final.json` 记录的最终版本。观测器修改未重新生成或改变 RTL。

事件文件逐活跃周期记录架构分配/提交、分支决策、dot 输入输出、redirect/flush/精确异常，最多 200000 行；完整架构分配和提交用于识别 ROB 重用。默认不产生 VCD/FST。仅首对观察开关比较开启架构提交文本，所有事件可离线重新审计：

```bash
python3 stage2/e16-events/audit.py LOG EVENT.jsonl \
  --symbols stage2/e16-events/build/short.symbols --out NEW.audit.json
python3 stage2/sew16/check-preservation.py --out NEW.preservation.json
```

长构建/整核运行按 40 分钟间隔检查，不在等待期间反复查询命令行。该实验是指定短场景和种子的动态证据，不代表所有控制流的形式证明，也不提供性能或物理功耗结论。
