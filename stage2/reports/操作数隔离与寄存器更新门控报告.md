# vdot 操作数隔离与寄存器更新门控

范围：VDot8 和普通 VIMac 分支的操作数隔离、分支寄存器更新使能。指令合同仍为 v0.1；不是新增 ISA 版本。不修改 NEMU、译码、MGU、共享流水或 yunsuan 子模块；不引入物理时钟门控。

## 设计与验收边界

点积第一级使能为 `regEnable(1) && inIsVdot`，第二级为 `regEnable(2) && ctrlVec(1).fuOpType == vdot`。第二级必须使用对应流水级的指令类型，不能使用当前输入类型；混发时两条不同指令可以同时在两条通路的不同级推进。

VDot8 使用第一级使能在乘法前隔离两个低 64 位操作数。高 64 位从未参与点积，不新增隔离逻辑。原有 8×16 位乘积、19 位求和、低 32 位符号扩展和高 96 位零保持不变；未初始化的数据寄存器仍不在无效周期构成架构结果。

普通 VIMac 输入使能保留原 `io.in.valid` 约定，仅排除点积：`io.in.valid && !inIsVdot`。数据在 split/reorganize 前隔离，运算控制固定为默认 vmul/e8，子模块输入控制在无普通请求时固定。复用 VIMac64b 内部 `fire` 和 `fireS1` 的寄存器使能，不使用年轻指令类型关闭仍在完成的较老普通乘法。

不改变共享 valid、ready、ROB/pdest 标签、输出选择、vxsat、向量写使能和非法配置检查。取消由既有控制流水屏蔽，允许被取消的物理数据留在内部寄存器；不得将内部保持值解释为提交结果。当前 wrapper 测试夹具是固定两周期、ready=true，不声称验证任意背压协议。

这项改动主要减少无用数据翻转，不删除运算单元。`RegEnable` 不保证物理门控时钟；没有实际综合时序、面积、工艺映射和功耗分析前，不报告节能百分比、PPA 或频率提升。MGU 和共享数据流水仍可能翻转。

## 实测活动变化（不是功耗）

比较完全相同的固定 seed 混合回归。寄存器统计为每个时钟上升沿前后确定值的 XOR bit count；操作数统计为每周期采样输入之间的 XOR bit count。不是按电容加权的能耗，不统计组合毛刺或时钟翻转；不能外推为整核节能率。

| 观测组 | 优化前 bit flips | 优化后 bit flips |
| --- | ---: | ---: |
| 点积 8 个乘积寄存器 | 19052 | 4580 |
| 点积 19 位求和寄存器 | 2859 | 669 |
| 两个普通 MAC 的 Wallace 第一级数据寄存器 | 117326 | 100444 |
| 两个普通 MAC 的第二级结果寄存器 | 38968 | 29696 |
| 点积乘法输入，逐周期采样 | 22352 | 7344 |
| 普通 MAC 三个数据输入，逐周期采样 | 67112 | 56294 |

所选四组寄存器合计 178205 → 135389，减少约 24.03%；这只描述该输入序列中的这些寄存器活动。未覆盖 MGU、共享数据/控制流水、物理时钟、电容、路由和综合优化；综合工具也可能重写隔离逻辑，须在实际映射网表重新确认。
