## 二、公开材料应包含什么

从[依赖清单](../manifest/仓库关系.md)准备同级的 `XiangShan`、`NEMU`、`nexus-am`、`DRAMsim3` 和 `env.sh`；子模块版本另见随附机器清单。作品目录提供测试源码、构建与复核脚本、三份当前补丁、评审文档、图片和选定原始证据。

发布前必须确认新增文件已包含在交付目录中。仅导出旧仓库提交，可能漏掉尚未纳入版本管理的脚本和中文文档。构建目录、全部历史 emu、完整大波形与私人提交材料分别管理。历史性能数据的公开复算可以不携带 emu、参考库、ELF 和测试镜像。

逐项内容见[发布材料清单](发布材料清单.md)。实际导出入口如下；目标目录必须尚不存在，且位于作品目录之外：

```bash
python3 scripts/test-public-release.py
python3 scripts/export-public-release.py --out ../releases/sew16-public-next/cie2026-skito-SKIProject
```

导出器显式收集当前未纳入版本管理的源码和中文文档，保留文档引用的文本证据与性能复算材料；拒绝携带 ELF、完整 VCD、构建目录和私人提交材料。历史大附件的链接仅在发布副本中改为归档说明，原开发文档和附件不动。

示例使用新的 `sew16-public-next` 目录，避免与已交付的 `sew16-public` 冲突。实际发布位置见[材料清单](发布材料清单.md)，不要直接向已有目录重复导出。

导出后，在发布目录核对逐文件清单、文档链接及性能数据：

```bash
python3 scripts/check-public-release.py --out /tmp/public-release-check.json --with-performance-data
```

清单检查会拒绝缺项、大小变化和未登记文件，包括导出后误放入的私人材料。该入口用于发布副本；开发目录中的历史完整审计继续使用原入口。

公开目录至少保留本手册、[补丁说明](../stage2/patches/vdot补丁选择与应用说明.md)、[版本选择](核与参考库版本选择.md)、当前设计和验收报告。不要把内部原始记录的绝对路径改写为新的实验记录；复核器在读取时映射到包内路径。

## 三、新一轮独立目录实跑

本节是根据实际命令整理的再次执行模板，所有输出使用新路径。已有成功结果只需只读复查，不必重建或重新仿真。实际构建用的是发布候选树；收尾后的源码包增加了文档和证据，41 份程序编译输入及 20 个补丁文件与实跑工作树一致，见[复现报告](../stage2/reports/公开包独立目录复现报告.md)。

### 1. 准备依赖与作品目录

从解压后的发布作品目录执行。先把 `REPRO_WORKSPACE` 改为本机尚不存在的绝对路径；后续进入该变量指定的目录，不根据调用位置猜测相对路径：

```bash
REPRO_WORKSPACE="/请替换为新目录的绝对路径/sew16-next"
python3 scripts/prepare-clean-workspace.py --destination "$REPRO_WORKSPACE"
cd "$REPRO_WORKSPACE/cie2026-skito-SKIProject"
source ../env.sh
```

准备脚本先检出清单中的 24 个依赖仓库，再复制发布作品树、生成新工作区的 `env.sh`，最后应用 XiangShan、NEMU 和 Difftest 三份补丁。使用此入口后，不再手动重复应用补丁；手动准备基线时才单独按[补丁说明](../stage2/patches/vdot补丁选择与应用说明.md)操作。

有本地依赖仓库时，准备命令可附加 `--source-workspace 本地依赖工作区绝对路径`，只读取 Git 对象。所需版本不在本地时从指定上游补取，不复制本地未提交源码或构建产物。本轮最终工作树为 `xs-env/cleanworkspaces/sew16-v2/`，本地对象来源为前期准备的 `xs-env/cleanworkspaces/sew16-v1/`。

`--resume` 只恢复作品尚未复制时的依赖检出失败，要求已有依赖源码仍干净。SoftFloat 的受版本管理 `build/` 含 Makefile，属于源码。NEMU 的五项隐式仓库已列入清单；上游随附资源仍按指定版本保留，实际差分使用新编译的 NEMU 库。

### 2. 工具环境

需要 Git、Make、C/C++、Python、Flex/Bison、Java、Mill、Verilator、RISC-V 交叉工具链、firtool，以及 zlib/zstd、SQLite 等开发库。实际版本见 `manifest/release-toolchain.json`：本轮使用 Mill 0.12.3、Java 21、Verilator 5.048、GCC/RISC-V GCC 15.2 和 firtool 1.62.1。

本轮 CMake 不在 PATH 中，曾在工作区工具目录解包 CMake 4.2.3 及缺少的运行库，命令与包名见[本地工具记录](../stage2/logs/clean-reproduction/tool-setup.json)。使用同样布局时，将 `REPRO_TOOLS` 改为实际工具目录：

```bash
REPRO_TOOLS="/请替换为工具目录的绝对路径"
export VDOT_CMAKE="$REPRO_TOOLS/cmake-root/usr/bin/cmake"
export LD_LIBRARY_PATH="$REPRO_TOOLS/cmake-root/usr/lib/x86_64-linux-gnu${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
export XDG_CACHE_HOME="$REPRO_TOOLS/cache"
export COURSIER_CACHE="$REPRO_TOOLS/cache/coursier/v1"
```

上述变量对应本轮的本地解包和下载缓存布局；已正常安装工具时按实际位置设置。Mill 启动器和 Coursier 下载缓存可以复用，本轮没有复用工程类文件或对象文件。firtool 可通过 `VDOT_FIRTOOL` 指定；构建脚本默认查找已验证的本机安装位置。

### 3. 构建参考库、主存模型、六份软件镜像与整核

以下均从新工作树的作品目录执行。NEMU 与 DRAMsim3 在实际过程中并行准备；这里按顺序列出，便于手工核对：

```bash
make -C ../NEMU vdot-v0.1_defconfig 'git_commit='
make -C ../NEMU -j2 BUILD_DIR="$NEMU_HOME/build/sew16" 'git_commit='
python3 stage2/sew16/check-reference.py ../NEMU/build/sew16/riscv64-nemu-interpreter-so
bash scripts/prepare-vdot-dramsim.sh
make -C stage1/hello-xiangshan ARCH=riscv64-xs
make -C stage1/vector-add ARCH=riscv64-xs
make -C stage2/contract-tests ARCH=riscv64-xs KIND=functional
make -C stage2/contract-tests ARCH=riscv64-xs KIND=control
make -C stage2/sew16 ARCH=riscv64-xs
make -C stage3/sew16-perf ARCH=riscv64-xs
bash scripts/build-vdot-sew16-core.sh --check
bash scripts/vdot-step.sh recheck-core-build bash scripts/build-vdot-sew16-core.sh
```

软件镜像在本轮整核构建期间完成编译；以上串行顺序只是再次执行模板。`--check` 只做预检。已有 emu 或 FIRRTL 时脚本拒绝覆盖，应先核对目录和旧记录，不直接删除产物。本轮 2861 秒仅为整核构建耗时，不包括其后的长仿真。

### 4. 在新工作树执行架构回归

发布包带有 `stage2/logs/clean-reproduction/` 的成功参考记录。`run-clean-regressions.py` 默认也向该固定目录写入，直接重复运行会触发拒绝覆盖保护；本轮协调脚本运行时，候选树中尚未收录这些收尾证据。对最终发布树的新一轮实跑，使用下面的手工入口和新记录目录，保留随附参考记录。

```bash
REPRO_RECORD_DIR="$(mktemp -d "$PWD/stage2/logs/recheck.XXXXXX")"
REPRO_EMU="$NOOP_HOME/build/sew16-fixed8/emu"
REPRO_REF="$NEMU_HOME/build/sew16/riscv64-nemu-interpreter-so"
bash scripts/vdot-step.sh recheck-hello "$REPRO_EMU" --diff="$REPRO_REF" -i "$PWD/stage1/hello-xiangshan/build/cie2026-stage1-hello-riscv64-xs.bin" --max-cycles=300000 --seed=101
bash scripts/vdot-step.sh recheck-vadd "$REPRO_EMU" --diff="$REPRO_REF" -i "$PWD/stage1/vector-add/build/cie2026-stage1-vector-add-riscv64-xs.bin" --max-cycles=300000 --seed=101
bash scripts/run-vdot-contract-tests.sh --check
bash scripts/run-vdot-contract-tests.sh
set -o pipefail
bash scripts/vdot-step.sh recheck-sew16-regression bash scripts/run-vdot-sew16.sh | tee "$REPRO_RECORD_DIR/sew16-coordinator.log"
REPRO_FULL_LOG="$(sed -n 's/^\[sew16 regression COMPLETE\] //p' "$REPRO_RECORD_DIR/sew16-coordinator.log")"
python3 stage2/sew16/check-core.py "$REPRO_FULL_LOG" --coordinator "$REPRO_RECORD_DIR/sew16-coordinator.log" --out "$REPRO_RECORD_DIR/sew16-audit.json"
```

两份合同镜像由 Makefile 的 `print-image` 查询：功能目录为 `build/contract-v2-functional-r0-seed0x56444f54/`，控制目录为 `build/contract-v2-control-r0-seed0x56444f54/`，均相对 `stage2/contract-tests/`。runner 不回退到旧平铺镜像。

验收须同时确认差分开启、预期 PASS、GOOD TRAP 和真实退出 0。合同功能应通过 52 项既有合法检查、10 项非法检查和 32 项 e16 合法检查；完整扩展应通过 1564 项 e8、836 项独立 e16 及共享套件额外 32 项 e16 检查。新日志路径由脚本输出，完整扩展的协调日志与审核 JSON 写入新建的记录目录。架构控制通过与内部 ROB 取消审计分开，后者见[短实验](../stage2/e16-events/e16短控制实验操作手册.md)。

### 5. 两次性能烟雾

本轮两个烟雾的 profile=1、wide=1、初始化 seed=101、数据种子相同，first 分别为 0/1。下面使用全新的临时前缀，源码包随附的旧日志不会被覆盖：

```bash
python3 - <<'PY'
from pathlib import Path
import sys
import tempfile
sys.path.insert(0, str(Path('stage3/sew16-perf').resolve()))
import common as C
directory = Path(tempfile.mkdtemp(prefix='recheck-perf-', dir=C.ROOT/'stage3/logs'))
for first in (0, 1):
    C.run(directory/'smoke', f'first{first}', 'new', 1, first, 1, 0x56444f54, 101)
PY
```

每进程应保留 120 条预热/计时采样，以及每位宽、每实现各 40 次完整结果/CSR 等价性检查。两进程共 240 条采样和 320 次等价性检查，不替代八进程正式统计。长进程每半小时检查一次，报错时保留原输出，再处理失败步骤。

### 6. 模块波形与收集恢复

本轮在新工作树的 XiangShan 目录执行了以下一个混发测试，只生成一份模块 VCD：

```bash
(
  cd "$NOOP_HOME"
  mill -i -Djvm-xmx=3G -Djvm-xss=16m xiangshan.test.testOnly xiangshan.backend.fu.vector.VDotIntegrationTest -- -z "preserve randomized"
```

Mill 将波形放在 `out/xiangshan/test/testOnly.dest/sandbox/test_run_dir/` 下，不是顶层 `test_run_dir/`。本轮第一次仅收集失败，测试已成功；修正查找后复用了原 VCD，没有再次运行测试。`--finish-wave-only` 是本轮已有状态文件的专项恢复入口，不是发布包的新一轮默认命令。波形由 `check-isolation.py` 审核后再压缩，`render-clean-module-wave.py` 只从压缩文件提取两张图。

## 四、搬迁后复算已保存性能数据

在公开作品目录中执行：

```bash
python3 scripts/review-submission.py --suite performance-data --out /tmp/public-performance-review.json
```

该入口读取原始日志，重新检查运行种子、差分与实际退出、精确有符号整数 oracle、采样顺序、分析源码与协议，然后重算全部统计并比对 1920 行 CSV。原记录保持原样；包内文件缺失时直接失败，不从原开发目录找替代品。作品目录可以搬迁和改名。

本模式不核验历史 emu/参考库/镜像身份、参数覆盖文件、计时事件或报告正文，这些项目在结果中明确标为 `NOT_AUDITED`。开发目录保留完整材料时，继续使用原完整审计：

```bash
python3 scripts/review-submission.py --suite performance --out /tmp/full-performance-review.json
```

调用 `review-public-data.py` 的 `--list-files` 可列出本模式所需材料，输入参数为已保存的 `.results.json`。复制清单列出的相对路径并保留目录结构即可；清单包含原始日志、结果、统计、CSV、分析源码及其修订记录，不包含大二进制。该清单只服务于数据复算，不能代替整个比赛交付包。
