# 核、参考库、测试与补丁版本选择

本页统一当前功能和性能验收入口。所有相对路径和命令均从作品目录 `cie2026-skito-SKIProject/` 执行。

第一阶段新增的[Hello 截图](../stage1/hello截图.png)使用保留的 `XiangShan/build/emu` 和随附参考库，只证明 Hello 环境验证通过；它不改变下方 e8/e16 的推荐组合，也不作为该组合的点积功能或性能证据。两次 Hello 运行的配置和周期见[阶段一验收](../stage1/docs/环境与RVV基线验收.md)。

## 当前推荐：sew16-fixed8

日常功能验收选择固定八项 e8/e16 版本，使用以下完整组合：

| 对象 | 唯一对应入口 |
| --- | --- |
| 整核 emu | `../XiangShan/build/sew16-fixed8/emu` |
| NEMU 参考库 | `../NEMU/build/sew16/riscv64-nemu-interpreter-so` |
| 测试源码 | `stage2/sew16/` |
| 测试镜像 | `stage2/sew16/build/cie2026-stage2-vdot-sew16-riscv64-xs.bin` |
| 完整运行命令 | `bash scripts/run-vdot-sew16.sh` |
| 构建命令 | `bash scripts/build-vdot-sew16-core.sh`，软件/参考库命令见[扩展手册](../stage2/sew16/固定八项e8e16扩展操作手册.md) |
| 主设计说明 | [当前 e8/e16 设计](../stage2/docs/vdot指令设计说明.md) |
| 已完成验收 | [扩展报告](../stage2/reports/固定八项e8e16实施与验收报告.md)、[原始审核 JSON](../stage2/logs/20261026-sew16-core-audit.json) |
| 配套补丁 | [补丁选择说明](../stage2/patches/vdot补丁选择与应用说明.md)中的 `xiangshan-vdot-sew16-fixed8.patch` 和 `nemu-vdot-sew16-fixed8.patch` |
| 构建兼容补丁 | `difftest-sync-compat.patch`；`bash scripts/prepare-vdot-difftest.sh --apply` 应用或确认就绪 |

合同为 VLEN=128、SEW=8/16、LMUL=1、VL=8、vm=1、vstart=0、vill=0 且向量状态开启。e8 使用源低八字节，结果符号扩展至低 32 位，高 96 位零；e16 使用全部八半字，结果符号扩展至低 64 位，高 64 位零。ta/ma 均接受。两级固定延迟、单 uop，不累加 oldVd。

上述推荐入口没有改写磁盘上的 `build/emu`，也没有更改旧通用脚本的默认值。`run-vdot-sew16.sh` 内部固定选择整组 emu/ref/image，初始化 seed=101；它不读取 `VDOT_EMU` / `VDOT_REF_SO` / `VDOT_IMAGE`，也不转发命令行参数。四个数据种子在同一个测试镜像中执行。

## 优先只读复核已有成功结果

本轮新核已完成构建与差分；查看[扩展报告](../stage2/reports/固定八项e8e16实施与验收报告.md)即可阅读结论。以下命令只复核现有证据，输出新 JSON，不启动 CPU：

```bash
python3 scripts/review-submission.py --suite function --out /tmp/function-review.json
python3 scripts/review-submission.py --suite preservation --out /tmp/preservation-review.json
```

需要重新验收硬件或镜像时，完整运行命令为：

```bash
bash scripts/vdot-step.sh sew16-core-regression bash scripts/run-vdot-sew16.sh
```

成功要求为差分开启、e8 检查 1564、e16 检查 836、四个数据种子、控制检查、GOOD TRAP、进程与审核退出 0。该命令不生成整核波形。后续长时间构建/仿真每 40 分钟检查一次。

## 历史版本的匹配组合

| 版本 | emu（相对作品目录） | 参考库 | 测试/用途 |
| --- | --- | --- | --- |
| v0.1，仅 e8 | `../XiangShan/build/emu` | `../NEMU/build/riscv64-nemu-interpreter-so` | `stage2/vdot-tests/`；`run-vdot.sh` 无环境覆盖时选择本组 |
| P1，仅 e8 | `../XiangShan/build/p1-oldvd/emu` | 同上旧参考库 | 原功能镜像；用对应历史手册显式选核 |
| operand-isolation，仅 e8 | `../XiangShan/build/operand-isolation/emu` | 同上旧参考库 | 原功能镜像及 `stage2/control-tests/`；旧四进程正式性能数据属于本组 |
| sew16-fixed8，e8/e16 | `../XiangShan/build/sew16-fixed8/emu` | `../NEMU/build/sew16/riscv64-nemu-interpreter-so` | `stage2/sew16/`；当前推荐组合 |

旧 `run-vdot-control.sh` 默认使用 operand-isolation 核和旧参考库。`run-vdot.sh`、`run-vdot-control.sh` 的环境覆盖只服务于显式历史选路，不会自动识别或适配新 ISA 合同。旧控制手册中的构建命令也对应历史 e8 源码版本；当前源码已经升级，复现旧硬件需使用归档/匹配的旧源码。

共享 `vdot-tests` / `control-tests` 源码现在由 `stage2/test-contract.h` 选择合同：默认 0 保留旧 e8-only，当前适配器显式设为 1，改用 e32/e64 非法例并校验实际 VL=4/2。NEMU API 脚本必须传 `--contract e8-only` 或 `--contract e8-e16`。旧已构建镜像的合同不会随源码升级改变，不能直接配新核。

当前旧套件适配入口为[合同适配手册](../stage2/contract-tests/旧测试约定适配手册.md)，运行 `bash scripts/run-vdot-contract-tests.sh`；它串行执行独立新建的功能/完整控制镜像。原 `stage2/sew16/` 完整扩展验收仍为主入口，原成功镜像保持；它的源码适配器也已改为显式选择新合同。新控制适配的架构通过不等于旧四独立初始化进程或内部取消波形覆盖。

## 性能和历史证据的版本边界

当前性能入口为 [e8/e16 v4 协议](../stage3/sew16-perf/性能测量与复核手册v4.md)和[八进程正式报告](../stage3/reports/e8e16正式性能分析报告v4.md)，镜像为 `stage3/sew16-perf/build/cie2026-vdot-sew16-perf-v4-riscv64-xs.bin`。正式新核/ref 与上面的功能组合一致；旧核对照显式使用 `operand-isolation/emu`＋旧参考库，同一镜像仅启动参数跳过 e16。只读复核用 v4 手册的 `review.py`，无需重跑。

现有[v3 测量手册](../stage3/docs/历史隔离核性能测量与复核手册v3.md)、[历史四进程报告](../stage3/reports/隔离核正式性能分析报告v3.md)、[隔离活动报告](../stage3/reports/P1至隔离核优化对比报告.md)保留旧 e8 核/旧协议身份，不混入 v4。功能回归总周期不代替加速比，新核仍无物理 PPA 数据。

旧版本的实际取消波形、四进程测量和历史失败记录保持其原身份。 新增[新核 e16 短控制事件实验](../stage2/reports/e16整核取消与独立初始化实验报告.md)：四独立初始化进程、实际执行后取消与未提交、观察开关对照均通过；不生成完整波形。其专用组合是 `../XiangShan/build/sew16-events/emu`、同一新参考库及 `stage2/e16-events/build/cie2026-e16-events-short-riscv64-xs.bin`，构建/运行及只读重审见[手册](../stage2/e16-events/e16短控制实验操作手册.md)。日常完整功能入口仍为上面的 `sew16-fixed8`，无需为复核重跑。

四个 seed 的有效事件轨迹相同，不声称四种不同控制历史。当前能力仍不包含可变 VL、VLEN=256、SEW=32/64、mask 或非零 vstart。

## 稳定的交付结果复核入口

以下命令只读取已完成结果，不启动仿真。输出文件须使用不存在的新路径。

```bash
python3 scripts/review-submission.py --suite function --out /tmp/function-review.json
python3 scripts/review-submission.py --suite control --out /tmp/control-review.json
python3 scripts/review-submission.py --suite performance --out /tmp/performance-review.json
python3 scripts/review-submission.py --suite preservation --out /tmp/preservation-review.json
```

具体材料位置和原执行记录由内部日志保存。

公开包搬迁后、不携带历史仿真器和镜像时，可用 `python3 scripts/review-submission.py --suite performance-data --out /tmp/public-performance-review.json` 复算性能原始日志、统计和完整 CSV，仍严格返回 3。该入口明确不审核二进制身份、参数覆盖、计时事件和报告正文。整核构建预检、合同测试新镜像目录及完整复现流程见[公开交付手册](公开交付与干净复现操作手册.md)。

同主机独立目录 `cleanworkspaces/sew16-v2/` 已从指定基线和发布候选材料重建同一 `sew16-fixed8` 设计，Hello/vadd、合同功能与控制、完整扩展、两个性能烟雾及模块混发检查全部通过，见[复现报告](../stage2/reports/公开包独立目录复现报告.md)。它是同版本独立重建，原开发目录的推荐组合和历史产物保持。新完整扩展镜像执行了共享套件新增的 32 项 e16 正例，不能拿其回归总周期直接对比原旧镜像。

发布源码包本身不带这组构建产物：只读复查可直接使用包内数据入口，实跑则需先在新工作树构建。最终包已包含成功参考日志，自动协调器的固定输出目录不可直接重复使用；新一轮按[手册](公开交付与干净复现操作手册.md)的手工入口与新记录路径执行。
