# RVV 向量加法波形分析

## 1. 目标与结论

本步骤为标准 `vadd.vv` 建立从指令编码、向量执行端口到写回数据的波形基线，为下一阶段加入自定义 `vdot.vv` 时提供可对照的硬件路径。

结论：波形中识别到 10 次向量整数加法执行和 10 次对应写回；`vsew=10`（SEW=32）、`vlmul=000`（LMUL=1）、执行端口始终 ready。首组最低元素为 `100 + (-40) = 60`，末组有效元素为 `28 + 68 = 96`，与软件检查一致。

## 2. 动态周期定位

静态反汇编：

```text
PC       0x80000246
编码     0x02848557
指令     vadd.vv v10, v8, v9
```

先启用 commit trace，并通过逐步缩小最大周期范围确定指令首次提交发生在周期 2900–2950。完整跟踪显示该 PC 动态提交 10 次，符合 `37 = 9 × 4 + 1` 的分块结果。

波形窗口选择为 2850–3300，既包含首个 `vadd.vv` 进入向量执行路径前的状态，也覆盖全部 10 次执行和写回。

## 3. 波形生成

```bash
./scripts/dump-vector-add-wave.sh
```

等价核心命令：

```bash
XiangShan/build/emu \
  --diff=XiangShan/ready-to-run/riscv64-nemu-interpreter-so \
  -i stage1/vector-add/build/cie2026-stage1-vector-add-riscv64-xs.bin \
  --dump-wave \
  --wave-path=stage1/waveform/vector-add-vadd.vcd \
  -b 2850 -e 3300
```

本次生成结果：


## 4. 关键路径与信号

| 阶段 | 关键波形信号 | 用途 |
|---|---|---|
| 分发到向量队列 | `io_toIssueBlock_vfUops_*_valid` | 向量 uop 有效 |
| 指令识别 | `io_toIssueBlock_vfUops_*_bits_instr` | 匹配 `0x02848557` |
| 程序计数器 | `io_toIssueBlock_vfUops_*_bits_pc` | 匹配 `0x80000246` |
| 执行握手 | `io_toExus_vf_*_valid/ready` | 确认 uop 被向量执行端口接收 |
| 操作类型 | `io_toExus_vf_*_bits_fuOpType` | 本次稳定为 `001000000` |
| 向量配置 | `..._bits_vpu_vsew/vlmul` | `10/000`，即 SEW=32、LMUL=1 |
| 操作数 | `..._bits_src_0/src_1` | 两个 128-bit 向量源操作数 |
| 写回 | `io_fromWB_wbData_13/15_valid` | 本用例实际使用的两个写回通道 |
| 写回数据 | `io_fromWB_wbData_13/15_bits_data_0` | 128-bit 加法结果 |

实际执行周期：

```text
2914, 2937, 2960, 2986, 3006,
3012, 3019, 3043, 3063, 3070
```

实际写回周期：

```text
2916, 2939, 2962, 2988, 3008,
3014, 3021, 3045, 3065, 3072
```

每次执行到对应写回相差 2 个周期。本次执行在 `vf_1_0` 和 `vf_0_0` 两个端口间分配，对应写回通道 15 和 13。

## 5. 自动解析

```bash
./scripts/analyze-vector-wave.sh
```

解析脚本不依赖固定 VCD 标识符，而是从 `$var` 声明按信号名建立映射，随后提取执行握手、配置、最低 32-bit 输入和写回结果。脚本要求执行计数和写回计数均严格等于 10，否则返回非零状态。

文本结果位于 `stage1/logs/vector-add-wave-analysis.log`。

## 6. 对 vdot.vv 的直接用途

后续实现自定义 `vdot.vv` 时，应复用本文件中的观察点，依次核查：

1. 自定义编码和 PC 是否进入 `vfUops` 路径。
2. 译码后的 `fuType/fuOpType` 是否路由到目标向量整数执行单元。
3. `vsew/vlmul/vstart` 和 mask 是否与指令规范一致。
4. 两个 128-bit 源操作数是否正确读取。
5. 点积结果、物理目的寄存器和 ROB 索引是否正确写回。
6. commit 次数、差分结果及最终软件校验是否一致。
