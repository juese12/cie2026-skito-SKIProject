# RVV 向量加法指令执行过程

## 1. 验证目标

在未修改香山 RTL 和 NEMU 的基线环境上，验证标准 RVV 整数向量加法链路可用，为后续自定义 `vdot.vv` 提供对照基线。

验收条件：

1. RISC-V 交叉编译器能编码 RVV 1.0 指令。
2. XiangShan 能执行 `vsetvli`、向量加载、`vadd.vv` 和向量存储。
3. NEMU 差分测试全程无 mismatch。
4. 37 个 `int32_t` 结果全部匹配标量参考值。
5. 仿真以 `HIT GOOD TRAP` 和状态码 0 结束。

## 2. 测试设计

输入数组包含 37 个元素：

```text
A[i] = 3 * i - 40
B[i] = 100 - 2 * i
期望 C[i] = A[i] + B[i] = 60 + i
```

37 不是常见 VLMAX 的整数倍，因此能够验证循环分块和最后一个不足 VLMAX 的尾块。C 程序负责初始化、调用和逐元素核对；汇编程序负责实际 RVV 运算。

核心汇编序列：

```asm
vsetvli t0, a3, e32, m1, ta, ma
vle32.v v8, (a1)
vle32.v v9, (a2)
vadd.vv v10, v8, v9
vse32.v v10, (a0)
```

## 3. 构建过程

在作品仓库根目录执行：

```bash
./scripts/verify-stage1-env.sh
./scripts/build-vector-add.sh
```

构建参数：

```text
ARCH=riscv64-xs
MARCH=rv64gcv_zba
```

关闭编译器自动向量化，保证测试中的 `vadd.vv` 来自显式汇编，便于反汇编和波形定位。

构建日志：`stage1/logs/vector-add-build.log`。

## 4. 仿真过程

运行命令由脚本封装为：

```bash
XiangShan/build/emu \
  --diff=XiangShan/ready-to-run/riscv64-nemu-interpreter-so \
  -i stage1/vector-add/build/cie2026-stage1-vector-add-riscv64-xs.bin
```

执行：

```bash
./scripts/run-vector-add.sh
```

脚本保留本地完整性能日志，并将关键输出提取为可提交的 `stage1/logs/vector-add-run.log`。完整日志以 `.full.log` 结尾，受 `.gitignore` 排除。

## 5. 结果判定

成功日志必须同时包含：

```text
vector-add PASS: vadd.vv completed and all elements matched
HIT GOOD TRAP
[run] exit status: 0
```

若出现 `HIT BAD TRAP`、Difftest mismatch、缺少 PASS 标记或非零退出状态，则本阶段失败，不能进入自定义指令开发。

结论：所有五项验收条件均满足，标准 RVV 向量整数加法基线通过。

## 6. 与 vdot.vv 的关系

该基线确认了向量状态开启、向量寄存器读写、循环分块、访存、整数向量 ALU 和差分测试链路。后续实现 `vdot.vv` 时，可沿用相同的输入构造、标量参考、逐元素检查和日志抽取框架，将差异集中在指令编码、译码、执行单元语义和 NEMU 参考模型。
